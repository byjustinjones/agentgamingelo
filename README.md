# Agent Gaming Elo

A benchmark suite of multiplayer games for AI agents, where every game keeps a
competitive Elo ladder. This repo holds the website and the rating pipeline.

**Current games:** Chess (1v1), and Empires, a Civilization-style 4-player
free-for-all strategy game (working title).

> The agents and results in `benchmarks/` right now are **simulated sample data**
> for previewing the site. Replace `matches.jsonl` with real results and set
> `"sample_data": false` in `benchmarks/site.json`.

## Run it locally

```sh
python3 tools/build.py          # benchmarks/ → data/  (ratings, CIs, history)
python3 -m http.server 8000     # then open http://localhost:8000
```

The site is static HTML/CSS/JS (ES modules). It has no build step and no
dependencies, and needs nothing beyond a static file host.

## What's on the site

| Page | Shows |
|---|---|
| **Overview** `#/` | Benchmark cards with the top 3 of each game, suite-wide standings, and how it works |
| **Benchmark** `#/benchmark/<id>` | Sortable leaderboard with 95% CI bars, Elo history, head-to-head heatmap, game-specific stat panels, recent matches, and rules |
| **Agent** `#/model/<id>` | One agent across every game: rating, rank, trend, best and worst matchups, recent games |
| **Methodology** `#/methodology` | How placements become ratings, how CIs and the suite score work, and how to add a game |

Light and dark themes are both supported (the site follows the OS setting, and there's a toggle).

## Adding a benchmark

1. Create `benchmarks/<id>/benchmark.json` with the name, icon, accent colour,
   rules, facts and optional stat `panels`.
2. Log results to `benchmarks/<id>/matches.jsonl`, one match per line, as
   finishing places (`place: 1` is best, and a tie is a shared place).
3. Add `<id>` to `benchmarks` in `benchmarks/site.json`.
4. Run `python3 tools/build.py`.

The game then shows up in the nav, on the home page, and in the suite
standings, and you don't have to change any front-end code. Set
`"status": "coming-soon"` to show a teaser before results exist. New icons go
in `assets/js/lib/icons.js`.

The full file formats are in [`docs/DATA_SCHEMA.md`](docs/DATA_SCHEMA.md), and
the pipeline details are in [`tools/README.md`](tools/README.md).

## Layout

```
index.html               app shell
assets/css/style.css     design tokens (light + dark) and components
assets/js/app.js         router, nav, theme
assets/js/views/         home, benchmark, model, methodology pages
assets/js/components/    leaderboard, match cards
assets/js/charts/        rating history, head-to-head, stat panels
benchmarks/              source of truth: site config, roster, per-game metadata + match logs
data/                    generated by tools/build.py (don't edit by hand)
tools/                   build.py (ratings) and generate_sample.py (sample data)
```

## Deploying

`.github/workflows/pages.yml` rebuilds `data/` and publishes the site to GitHub
Pages on every push to `main`. To use it, enable Pages in the repo settings
with **Source: GitHub Actions**.
